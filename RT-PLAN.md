# Continuous Cataclysm — план

Цель — заменить пошаговую модель CDDA на честную непрерывную симуляцию:
float-позиции, движение в любом направлении, снаряды в полёте, окна атак, ИИ на
высокой частоте. Никаких ограничений шага. Системы, которые этому мешают,
переписываются.

Форк CDDA 0.I сохраняется как база не ради движения и боя — их мы и переписываем —
а ради всего остального: генерации карт, предметов, крафта, мутаций, бионики,
транспорта как механизмов, погоды, потребностей, эффектов, оверкарты, z-уровней,
освещения и десяти лет контента в JSON.

Рабочие заметки, разведка кодовой базы и список расхождений с апстримом —
в [RT-NOTES.md](RT-NOTES.md).

## Решения

| Вопрос | Решение |
|---|---|
| Координаты | **Полный float** |
| Меню | Мир на паузе при открытом меню — блокирующие диалоги CDDA остаются как есть |
| Рендер | SDL/`cata_tiles` до вертикального среза, решение по Unity — после |
| База | Форк тега `0.I` (6 июня 2026) |
| Апстрим | Совместимость не поддерживается |
| Сейвы | Ломаются, миграции не будет |

## Ключевое архитектурное решение

**Float-позиция становится хранилищем, целочисленный `tripoint` — производной
проекцией.**

```cpp
// Creature
struct pos3f { double x, y; int z; };   // Z остаётся целым: уровни — дискретные этажи
pos3f location;                          // авторитетная позиция

// существующий API сохраняется как проекция
tripoint_abs_ms pos_abs() const { return to_tile( location ); }
tripoint_bub_ms pos_bub() const;
// новый API для кинематики, коллизий, боя, рендера
const pos3f &pos_abs_f() const;
pos3f        pos_bub_f() const;
```

Это не компромисс. Местность в CDDA — воксельные данные: `map::ter`, `map::furn`,
`map::i_at`, FOV, освещение, генерация. Сэмплировать их по `floor(pos)` — ровно то,
что делает любая непрерывная игра с тайловым миром. Разница в том, что теперь
`floor(pos)` — вычисление, а не источник истины.

Замер по кодовой базе подтверждает конструкцию: **записей позиции около 115,
чтений — больше двух тысяч** (подробности в [RT-NOTES.md](RT-NOTES.md)).
Переписывать нужно записи и потребителей точной геометрии, а не две тысячи
запросов «в какой клетке это существо».

**Z остаётся целым.** Уровни CDDA — дискретные этажи. Непрерывный Z означал бы
полноценную 3D-физику и переделку всей карты. Переходы между уровнями остаются
дискретными событиями.

## Модель времени

Два такта, оба ведутся от одних wall-clock часов:

- **Кинематический такт — фиксированный шаг 60 Гц.** Движение, коллизии, снаряды,
  окна атак, steering, анимационные состояния.
- **Мировой такт — раз в игровую секунду.** `calendar::turn += 1_turns` и всё, что
  CDDA уже делает поход: поля, погода, температура, потребности, длительность
  эффектов, гниение, топливо и электрика транспорта, дальние планы NPC.

Мировой такт — не ограничение шага игрока, а стандартное разделение слоя действий
и фоновой симуляции: никто не пересчитывает голод 60 раз в секунду. Игрок при этом
не ждёт ничего и никогда.

**Пауза** — при открытом модальном экране кинематический цикл не крутится.
Симуляция однопоточна, блокирующие диалоги CDDA работают как есть.

## Замена экономики ходов

`int moves` уходит.

**Движение — не действие.** Это скорость. Максимальная скорость выводится из
`get_speed()`, стоимость местности становится множителем:
`mult = 2.0 / map::move_cost(p)`, `move_cost == 0` — непроходимо. Диагональ
перестаёт быть дороже — она просто направление.

**Остальные действия — конечный автомат с непрерывными фазами:**

```cpp
struct action_state {
    action_id id;
    float windup, active, recovery;   // секунды
    float elapsed;
    bool  cancellable_before_active;
};
```

Длительности выводятся из существующих стоимостей в moves:
`seconds = cost_moves / speed * RT_ACTION_SCALE`. Тем самым сохраняются стоимость
перезарядки, замаха, взаимодействий, влияние скорости, мутаций, боли, стамины и
эффектов — вся балансная работа десяти лет остаётся в силе, меняется единица
измерения.

**Индикатор занятости обязателен.** Действие на 3 секунды без видимого кулдауна
читается как зависание. Требование S5.

## Что выживает, что переписывается

**Выживает без изменений:** весь JSON-контент; генерация карт и оверкарты;
предметы; крафт; мутации, бионика, болезни; потребности и мораль; погода и
температура; освещение и FOV; звуки; фракции и миссии; диалоги; z-уровни;
сохранение мира и карты; `monster::plan()` и логика выбора цели, гнева, морали,
блуждания; расчёт урона, сопротивлений, попаданий, бросков уклонения и блока.

**Переписывается:**

| Подсистема | Что делаем |
|---|---|
| Позиция `Creature` | float-хранилище, целочисленные аксессоры как проекция |
| `creature_tracker` | Пространственный хеш; `creature_at(tripoint)` остаётся как shim, добавляются `creatures_overlapping(center, r)` и `nearest_creature()` |
| Движение | Интегрирование скорости, коллизия круг-против-сетки, разрешение по осям, скольжение вдоль стен |
| Экономика действий | `int moves` → `action_state` с фазами |
| ИИ монстров | `plan()` сохраняется, тиры 10 Гц вблизи / 1 Гц вдали. `move()`/`move_to()` → steering поверх тайлового `map::route()` |
| Ближний бой | Windup → активное окно (конус против кругов) → recovery |
| Дальний бой | Снаряд как сущность со скоростью, заметание отрезка по подшагам; урон через существующий `dealt_projectile_attack` |
| Активности | Непрерывный прогресс, прерываемый в любой момент |
| Тайминги эффектов, стамины, боли | Пересчёт с ходов на секунды |
| Транспорт | S10 |
| NPC | S9 |
| Рендер | float-позиции через существующий `offset`; суб-тайловый сдвиг камеры; `interval` 25 → 16 |

## Стадии

**S0 — разведка (опционально).** Stock 0.I, `TURN_DURATION = 1.0`, Safe Mode off.
Сбор наблюдений о том, как ощущается бой, когда мир не ждёт.

**S0b — сборка базы.** Форк @ `0.I`, vcpkg, MSVC, эталонный прогон тестов.

**S1 — float рядом с int.** Добавить `location_f`, держать в синхроне,
целочисленное поле остаётся авторитетным. Рендер начинает читать float.
*Готово:* поведение не изменилось, тесты совпадают с эталоном.

**S2 — переворот авторитета.** float становится хранилищем, `pos_abs()`/`pos_bub()` —
проекцией округлением. Самый рискованный коммит проекта; тесты — единственный гейт.

**S3 — пространственный индекс.** Замена `monsters_by_location`, снятие ограничения
«один монстр на клетку», `creature_at()` через перекрытие.

**S4 — непрерывная кинематика аватара.** Цикл 60 Гц + мировой такт 1 Гц, скорость
и коллизии для игрока, множители местности, пауза на модалках. Монстры пока шагают
по клеткам.

**S5 — модель действий.** `action_state` вместо `int moves` для аватара, индикатор
кулдауна.

**S6 — кинематика и ИИ монстров.** Steering, тиры обновления, направление взгляда.

**S7 — непрерывный бой.** Окна ближней атаки, снаряды в полёте, попадания по
геометрии. Результат — **вертикальный срез**.

**S8** — пересчёт таймингов. **S9** — NPC. **S10** — транспорт. **S11** — баланс.

## Decision Gate после S7

Вертикальный срез — первая точка, где видно настоящую картинку. Только тогда имеет
смысл решать про рендер.

- **SDL остаётся** — если картинки хватает.
- **Unity как renderer backend** — только вместе с абстракцией
  `Tile semantics → Tile resolution → VisualSprite[] → { SDLBackend, UnityBackend }`,
  причём `VisualSprite` обязан появиться **выше** уровня SDL-текстур. Прямая
  подмена «`SDL_RenderCopy` на sink» не сработает: `tileset` хранит текстуры в пяти
  световых вариантах, а `tileset_cache::loader` держит `SDL_Renderer_Ptr` сквозь всю
  загрузку. Unity-часть проектировать сразу GPU-driven: `GraphicsBuffer` +
  structured instance data + custom shader + `RenderMeshIndirect`;
  `RenderMeshInstanced` не подходит из-за лимита 1023 инстанса на вызов.
- **Промежуточный вариант** — CDDA рендерит в существующий `display_buffer`, Unity
  показывает текстуру и добавляет свет, частицы и постпроцесс. Дёшево, но
  1920×1080 RGBA ≈ 8.3 МБ/кадр ≈ 500 МБ/с при 60 fps.

## Границы подхода

**Достижимо** — темп в духе Project Zomboid: клеточная логика мира, непрерывные
часы, удержанное движение, плавная анимация, пауза.

**Недостижимо без замены симуляции** — и именно поэтому симуляция и заменяется:
столкновения внутри клетки, непрерывные координаты, суб-секундный тайминг
попаданий, окна атаки, полёт снарядов, хитбоксы, частота ИИ сильно выше 1 Гц.

## Верификация

- **Регресс контента:** некарантинная часть тестов после каждой стадии.
- **Детерминизм (S4+):** два прогона с одного сейва и одной последовательности
  ввода при фиксированном шаге 60 Гц дают одинаковые траектории. Без этого отладку
  боя вести невозможно.
- **Коллизии (S4):** автотест-полигон — проходы в одну клетку, углы, диагональные
  щели, движение вдоль стены на высокой скорости; ноль проникновений, ноль
  застреваний.
- **Фиксированность мирового такта (S4):** `calendar::turn` растёт 1.00 ± 0.02 в
  секунду независимо от активности игрока.
- **Отзывчивость (S5):** замер «SDL event timestamp → начало фазы windup», порог
  50 мс по p99.
- **Соответствие балансу (S5):** длительности сверяются с исходными стоимостями в
  moves при speed 80/100/130.
- **Производительность (S6):** 60 fps при 100+ монстрах в пузыре.
- **Снаряды (S7):** тест на туннелирование.

## Риски

1. **S2, переворот авторитета позиции** — самый опасный коммит. Митигация: S1
   заводит float в параллель без смены поведения, тесты служат гейтом, откат дешёвый.
2. **Одно-существо-на-клетку зашито в контракт, а не только в контейнер.**
   `creature_tracker::add()` документирует отказ при занятой клетке; `update_pos()`
   возвращает `bool`; `swap_positions()` существует именно поэтому. На S3 менять
   придётся контракт и все проверки возврата.
3. **Производительность ИИ.** Сотни монстров × 60 Гц нереальны; тиры по дистанции
   заложены, пороги подбирать замерами.
4. **Транспорт** (S10) — практически отдельный проект.
5. **NPC** (S9) — второй по объёму.
6. **Баланс** (S11) — главная неопределённость по срокам, дизайнерская, не техническая.
7. **Тесты** — часть набора придётся переписать.
8. **Сейвы** ломаются.

## Явно отложено

Непрерывный Z и 3D-физика; переписывание блокирующих диалогов в асинхронные (снято
выбором «пауза на меню»); мультиплеер; миграция сейвов 0.I; совместимость с модами,
которые лезут в движение и бой.

## План В

Ремейк на C# — последний вариант, не в критическом пути. Разумен только если
выяснится, что менять придётся ещё и то, что мы сохраняем ради контента.
