# Continuous Cataclysm — заметки форка

Форк [CleverRaven/Cataclysm-DDA](https://github.com/CleverRaven/Cataclysm-DDA) от тега **0.I**
(коммит `27939e29b8b4ddc081490d9f51de59a459c88df6`, 6 июня 2026).

Цель — заменить пошаговую модель на честную непрерывную симуляцию: float-позиции,
движение в любом направлении, снаряды в полёте, окна атак, ИИ на высокой частоте.
Всё остальное содержимое CDDA — генерация карт, предметы, крафт, мутации, бионика,
транспорт как механизмы, погода, потребности, эффекты — сохраняется.

Полный план и таблица прогресса по стадиям: [RT-PLAN.md](RT-PLAN.md).
Этот документ — рабочие заметки: расхождения с апстримом, разведка кодовой базы,
адреса точек вмешательства.

Апстрим-совместимость не поддерживается. Ветка работы — `rt-main`, remote `upstream`
оставлен только для справки.

## Сборка

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\rt-build.ps1
```

Скрипт сам находит Visual Studio через `vswhere`, импортирует её окружение,
подхватывает встроенные CMake и Ninja и конфигурирует сборку. Developer Command
Prompt не нужен.

| Ключ | Назначение |
|---|---|
| `-ConfigureOnly` | только конфигурация |
| `-Target cata_test` | собрать одну цель |
| `-Config Debug` | конфигурация сборки (по умолчанию `RelWithDebInfo`) |
| `-Fresh` | снести каталог сборки перед конфигурацией |

`VCPKG_ROOT` берётся из окружения, по умолчанию `D:/vcpkg`.

**Проверенное окружение на этой машине:** Visual Studio Build Tools 2026
(18.7.11911.148, `D:\VSBT`), MSVC 14.44 и 14.51, vcpkg на `D:\vcpkg`,
триплет `x64-windows-static`, генератор Ninja Multi-Config.

**Конфигурация:** `TILES=ON`, `CURSES=OFF`, `SOUND=OFF`, `TESTS=ON`,
`LOCALIZE=ON` (`msgfmt` берётся из Git for Windows), `DYNAMIC_LINKING=OFF`.

## Профилирование

```powershell
out\build\rt-msvc\src\RelWithDebInfo\cataclysm-tiles.exe --rt-profile 1
```

Игра на Windows собрана как GUI-приложение и своего stdout не имеет, поэтому флаг
сам открывает консольное окно (или подцепляется к консоли, из которой запущен) и
параллельно пишет `rt-profile.log` в текущий каталог. Аргумент — интервал в
секундах, по умолчанию 2.

```
--- rt-profile  1.00 s  |  world 0.00 turns/s  |  0.0 fps  |  cpu 2% of one core ---
scope                              calls   total ms    self ms   % wall    ms/call
sdl: poll for input                    0    1001.39    1001.39   100.0%    running
```

Читается так: **`% wall` — сколько прошло времени, `cpu` — сколько времени процессор
реально работал.** В примере игра стоит в главном меню: сто процентов стены в
ожидании ввода при загрузке процессора в два процента, то есть она ждёт, а не жжёт.
Расхождение этих двух чисел и есть ответ на вопрос «грузит или просто медленно».

- `world turns/s` — это будущий критерий S4 (мировой такт 1.00 ± 0.02 в секунду),
  он меряется с самого начала, а не будет прикручен потом.
- `self ms` — время за вычетом вложенных scope'ов. Без него отчёт был бы списком
  одних и тех же миллисекунд, пересказанных на каждом уровне вложенности.
- `running` в колонке `ms/call` — scope, который ещё не вернулся. Ожидание ввода
  выглядит именно так: время идёт, вызов не завершён. Отчёт печатается и изнутри
  цикла опроса ввода, иначе на простое, когда ни один ход не заканчивается,
  не печаталось бы вообще ничего — то есть ровно в интересном случае.

Инструментировано пока крупными фазами хода (см. разбор `do_turn` ниже): `monmove`,
`vehmove`, поля, предметы, кеши карты и обзора, звуки, отрисовка, ожидание ввода.
Это инструментирование, а не сэмплирующий профайлер: оно отвечает, какая фаза
съела время, но не какая строка внутри фазы. Для фазового цикла это правильный
размен, для точечной оптимизации внутри фазы понадобится настоящий сэмплер.

Выключенный профайлер стоит одну проверку булевой глобали на scope.

## Изменения относительно апстрима 0.I

Список ведётся вручную; каждый пункт — отдельный коммит, чтобы откат был тривиальным.

| Файл | Изменение | Причина |
|---|---|---|
| `msvc-full-features/vcpkg.json` | Убраны `sdl2-mixer` и `pdcurses`, добавлен явный `zlib` | Собираемся с `SOUND=OFF` и `CURSES=OFF` — эти зависимости никогда не линкуются, но в manifest-режиме vcpkg собирал бы их из исходников при каждой чистой сборке. `zlib` нужен явно, потому что `find_package(ZLIB REQUIRED)` в `CMakeLists.txt` безусловен. Вернуть звук — просто вернуть строки обратно |
| `build-scripts/MSVC.cmake` | `/TP` ограничен языком C++: `$<$<COMPILE_LANGUAGE:CXX>:/TP>` | Апстрим применял «считать любой файл C++» ко всем языкам. Апстрим этого не видит, потому что генератор Visual Studio пробу пропускает, а Ninja — выполняет. Для C++ флаг избыточен, а zstd теперь собирается как C, для чего и написан |

Скрипт гоняет `cata_test-tiles` с фиксированным зерном и лексическим порядком, пишет XML, и сравнивает список упавших тестов с эталонным — отдельно показывая регрессии и починенное |

## Результат S1

1159 тестов (1153 эталонных + 6 новых), падений 1 против 1 в эталоне, регрессий нет.

Что стоит помнить дальше:

- **`coord_point` конструкторы теперь ограничены `is_arithmetic`.** Разнесение
  одного `T` по параметру на ось само по себе сломало сборку: требование
  одинаковых типов случайно работало ограничителем, не давая двухаргументной
  форме перехватывать вызовы `(Subpoint, z)`, где она выигрывает у
  `(const Subpoint &, T z)`. Компилятор поймал это в 315 единицах трансляции.
  Ограничение теперь выражено явно — код строже апстримового.
- **Смещение в `cata_tiles` — не экранные пиксели.** `draw_sprite_at` масштабирует
  сумму `tile_type::offset + offset` на `tile_width / get_tile_width()`. Экранные
  пиксели отмасштабировались бы дважды. Вертикальная составляющая тоже конвертируется
  через ширину нативного тайла — так уже сделано в апстриме, и расходиться с этой
  конвенцией дороже, чем быть независимо правым насчёт неквадратных тайлсетов.
- **Смещение сущности — область видимости, а не параметр.** Существо рисуется
  несколькими спрайтами (тело, одежда, эффекты, всадник на маунте), и они обязаны
  разделять одно смещение. `scoped_entity_offset` вокруг всей `draw_critter_at`
  не может пропустить вложенный вызов, а протаскиваемый параметр — может.
- **Инвариант зеркала держится структурно.** `Creature::location` приватный, во
  всём дереве в него пишут ровно два сеттера. При переходе к S2 это же свойство
  делает переворот авторитета локальным.

## Результат S2

1161 тест (1153 эталонных + 8 наших), 40 264 126 успешных проверок, падений 1 против
1 в эталоне, регрессий нет. Единственное падение — всё тот же предсуществующий
`armor_protection`. `cataclysm-tiles.exe` собирается без предупреждений,
`--jsonverify` завершается кодом 0 и не оставляет `debug.log`.

Полный прогон занял 41 минуту против 39 у эталона. Замер разовый, доверительного
интервала у него нет, но направление ожидаемое: `pos_abs()` теперь считает `floor`
на каждый из более чем двух тысяч вызовов вместо чтения поля. Если это когда-нибудь
станет заметно, смотреть надо на `std::floor`: при x64-умолчании MSVC (SSE2) это
вызов CRT, а не инструкция `roundsd`, и заменяется на пару инструкций вручную.

Что стоит помнить дальше:

- **Позиция теперь одна.** `Creature::location` — `tripoint_abs_ms_f`,
  целочисленного поля нет. `pos_abs()` — проекция `to_tile()`, а `pos_bub()`,
  `pos_abs_sm()`, `pos_abs_omt()` строятся уже поверх неё, а не рядом с ней.
  Писатель ровно один, `set_pos_abs_f_only()`; целочисленные сеттеры проходят через
  него и ставят существо в центр названной клетки. Инвариант S1 сохранён
  структурно, а не соглашением.
- **`setpos_f` — отдельное имя, а не перегрузка `setpos`.** `tripoint_bub_ms` по
  всему дереву конструируется из фигурных списков, а `{ x, y, z }` из трёх целых
  подходит и целочисленному, и непрерывному типу одинаково хорошо. Перегрузка
  сделала бы такие вызовы неоднозначными — в `tests/wield_test.cpp:86` буквально.
- **`on_move()` принимает клеточные позиции.** Шаг внутри одной клетки — не
  перемещение для трекера, оверкарты и кешей света. `monster::on_move()` уже
  выходит рано, когда клетка не изменилась; на этом и поедут S3–S4, а тест
  «шаг внутри клетки не роняет монстра из трекера» это фиксирует.
- **Формат сейва пришлось трогать** — `Creature::store` писал поле напрямую.
  Клетка осталась точной целочисленной тройкой в `"location"`, дробная часть
  пишется рядом (`sub_tile_x`, `sub_tile_y`). Причина не в совместимости:
  `JsonOut` выводит `double` через поток с точностью по умолчанию, а шесть
  значащих цифр на масштабе абсолютных координат грубее целой клетки. На дробной
  части те же шесть цифр — миллионная доля клетки. Старые сейвы без этих полей
  читаются как центр клетки.
- **`coord_point_ob` по-прежнему задаёт subpoint целочисленным** (`coordinates.h`:
  `coord_point_mut<Point, coord_point_ob<point, …>>`), поэтому `.xy()` на
  непрерывной точке не соберётся — шаблонный член, ошибка только при
  инстанцировании. Пока не нужно; когда понадобится, обобщать до
  `typename Point::subpoint_type`.

## Результат S3a

1167 тестов, падений 1 против 1 в эталоне, регрессий нет. Дополнительно прогнан
эталонный набор в чистом виде — те же 1153 кейса, что и на S0b, имя в имя, без
единого нашего теста: состав падений тот же.

Что стоит помнить дальше:

- **Правило и хранилище разъехались.** «Один монстр на клетку» больше не свойство
  контейнера (у map один value на key, поэтому правило было невыразимо и
  неснимаемо), а две проверки в `creature_tracker::add()` и `update_pos()`. Индекс
  под ними спокойно держал бы двоих на клетке. Поэтому S3b — это правка проверок и
  тех, кто читает их возвращаемые значения, а не замена контейнера.
- **Записи лежат там, куда их положили, а не там, где существо.** `find()` отдаёт
  то, что подшито под клеткой, не спрашивая монстра, где он на самом деле, — ровно
  как вели себя ключи map. Отсюда и запасной скан всего индекса в
  `remove_from_location_map` для протухшей записи. Это сохранено намеренно: менять
  семантику и контейнер одним коммитом — это не иметь возможности сказать, что
  именно сломалось.
- **`swap_positions` обязан вынуть обе записи до того, как двинется хоть одно
  существо.** Записи подшиты по позиции; если сначала переместить, они останутся
  под клетками, на которых уже никого нет. В апстриме то же самое, по той же
  причине.
- **`monsters_overlapping` — только монстры.** Аватар и NPC в индексе не лежат,
  `creature_at` находит их перебором. Кому нужны все существа, тот проверяет их
  отдельно, как и сегодня.

## Ключевые точки вмешательства

Найдены и подтверждены чтением исходников 0.I.

**`src/coords_fwd.h` : 86** — система координат параметризована типом точки:
```cpp
template<typename Point, origin Origin, scale Scale> class coord_point_ob;
using tripoint_abs_ms = coords::coord_point<tripoint, coords::origin::abs, coords::ms>;
```
Float-вариант встраивается в существующую типобезопасность как
`coord_point<tripoint_f, origin::abs, ms>`, а не прикручивается сбоку отдельным
`vec2`. Ограничение: `coord_point_ob` (`coordinates.h:197`) жёстко задаёт subpoint
как `coord_point_ob<point, …>` — при добавлении float-точки это место нужно
обобщить до `typename Point::subpoint_type`.

**`src/creature.h`** — единственное поле позиции `tripoint_abs_ms location;`.
Суб-тайлового понятия нет нигде. (Состояние 0.I. После S2 поле осталось одно, но
стало `tripoint_abs_ms_f`.)

**`src/creature_tracker.h`** — `std::unordered_map<tripoint_abs_ms, shared_ptr_fast<monster>> monsters_by_location;`
Индекс структурно допускает не больше одного монстра на клетку. Ожидать, что это
допущение зашито и в поведение (блокировка движения, выбор цели, размещение
спавнов), а не только в контейнер.

**`src/monster.h`** — слой решений (`plan()`, `wandf`, `wander_pos`, `anger`,
`morale`, `path`) отделён от слоя актуации (`move()`, `move_to()`). Решения
переиспользуются, переписывается только актуация.

**`src/do_turn.cpp`** — анатомия хода прочитана построчно, границы разреза S4
проходят здесь. `do_turn()` начинается на строке 455 и делится на три части.

*Предфаза мира, 461–557.* `calendar::turn += 1_turns` (475), `gamemode->per_turn()`,
сброс кеша температур, `load_npcs()`, таймеры событий, `mission::process_all()`,
проверка угона транспорта, `stagger()` при застревании в стене, испуг верхового
животного, `process_mongroups()` (раз в сутки), движение орд и `spawn_monsters()`

`build_map_cache`, **`monmove()`** (666), `overmap_npc_move()` (периодически),
эмиссия полей от мебели и террейна (раз в 10 секунд), `mon_info_update`,
**`u.process_turn()`** (685) — именно здесь аватар получает moves на следующий
ход, — затем погодные эффекты.

Существенно: пополнение moves у аватара стоит **после** `monmove()`, в самом конце
хода. При разрезе это определяет, куда попадёт начисление в непрерывной модели.

**`src/do_turn.cpp:267` `monmove()`** — `critter.process_turn()`, затем
`while( critter.get_moves() > 0 … ) { critter.plan(); critter.move(); }`.
Ровно та граница «решение / актуация», которую S6 разделяет: `plan()` остаётся,
`move()` заменяется на steering. NPC обрабатываются там же (357–402) с защитой от
зацикливания: `count_limit = max( 10, guy.get_moves() / 64 )` и счётчик ходов без
трат moves.

**`src/handle_action.cpp`** — существующий частичный реалтайм: опция
`TURN_DURATION` («Realtime turn progression»), класс `user_turn` со
`steady_clock`, `has_timeout_elapsed()` при `moves_elapsed() > 100`,
`ctxt.set_timeout( 125 )`, `case ACTION_TIMEOUT: player_character.pause();`.
Готовая формула пересчёта wall-clock в moves.

**`src/cata_tiles.h`** — `draw_tile_at( …, int &height_3d, const point &offset )`:
пиксельный офсет уже в сигнатуре, рендер float-позиций почти бесплатен.
Обратная сторона — `tileset` хранит `std::vector<texture>` в пяти световых
вариантах, а `tileset_cache::loader` держит `const SDL_Renderer_Ptr &` сквозь всю
загрузку: рендерер сцеплен с SDL на уровне загрузки, не только отрисовки.

**`src/sdltiles.cpp`** — `refresh_display()` рендерит в off-screen `display_buffer`
(`SDL_RENDERER_TARGETTEXTURE`); `try_sdl_update()` гейтит кадры на `interval = 25`
мс (~40 fps).

## Эталон S0b

Прогресс по стадиям — в [RT-PLAN.md](RT-PLAN.md). Здесь только детали эталона,
с которым сверяется каждая последующая стадия.

`cataclysm-tiles.exe` — 446 объектов, ноль предупреждений, `--jsonverify` завершается
кодом 0 и не оставляет `debug.log`. `cata_test-tiles.exe` — 222 объекта, ноль
предупреждений.

| | |
|---|---|
| Тестов | 1153 |
| Проверок | 40 102 011 |
| Непрошедших проверок | 4 |
| Непрошедших тестов | **1** — `armor_protection` (`tests/iteminfo_test.cpp:1417`) |
| Время полного прогона | 39 минут |
| Зерно | фиксированное, `1` |
| Сборка | `cata_test-tiles`, RelWithDebInfo, 0 предупреждений |

Единственное падение — предсуществующее, на чистом апстриме 0.I, до единой нашей
правки в игровой код. Именно поэтому гейт сформулирован как «множество упавших
тестов не выросло», а не «все тесты зелёные»: сравнивается состав, а не ноль.

Полный прогон в 39 минут слишком дорог для каждой правки. Рабочий режим — гонять
подмножество по тегу (`tools/rt-test.ps1 -Filter "[melee]"`), а полный прогон
делать на границах стадий.

**Исключающий фильтр пишется как `~[tag]~[.]`, а не `~[tag]`.** Скрытые тесты
(`[.]`, бенчмарки и ручные) по умолчанию не запускаются, но это умолчание
действует, только пока спека нет. Спек из одних исключений снимает отсев, скрытые
тесты попадают в набор, и прогон обрывается на первом же из них — `~[rt]` у нас
умер на одиннадцатом тесте, на `Character_attacking_a_manhack`. Второй паттерн
`~[.]` возвращает отсев: набор `~[rt]~[.]` совпадает с эталонными 1153 кейсами
имя в имя.

**Число проверок зависит от окружения, а не только от кода.** Прогон S3 показал на
2.1 млн проверок больше, чем прогон S2, при неизменном составе падений. Причина
оказалась вне игры: `No_string_buffer_overlap_in_TranslationDocument` обходит все
языки, найденные в `lang/mo/`, и делает по две проверки на строку каждого `.mo`.
Файлы переводов генерирует `msgfmt` при сборке цели по умолчанию, и она случилась
между двумя прогонами: до неё каталога не было вовсе (в логе — `opendir [lang/mo/]
failed`), после — 27 языков и 2 141 281 проверка из ниоткуда. Разница прогонов была
2 141 394.

Отсюда два правила. Первое: **перед гейт-прогоном собирать цель по умолчанию**, а не
только `cata_test-tiles`, иначе набор переводов зависит от истории сборок. Второе:
`rt-test.ps1` сносит пользовательский каталог перед прогоном — игра намеренно
оставляет тестовый мир для разбора после падения, но мир, доживший до следующего
прогона, это состояние, которого тесты не создавали, и тесты, генерирующие карту,
начинают делать разный объём работы.

**Число проверок сравнивается поимённо.** `tools/rt-test.ps1` пишет рядом с XML
файл `*.stats.tsv` — по строке на тест-кейс, — и сверяет его с предыдущим таким
прогоном. Общая сумма проверок для этого не годится: у Catch2 в XML нет счётчиков
на кейс, только на секцию и на прогон, поэтому расхождение суммы само по себе
безадресно. Счётчик меряет не текст теста, а объём работы игры внутри него: цикл
«пока монстр не умрёт» даёт по проверке на итерацию, так что число меняется при
изменении поведения, даже когда тест зелёный и его исходник не трогали. Это
дешёвый детектор, а не доказательство эквивалентности: изменение, не меняющее
длину циклов, он не увидит.
